# Inventory REST contract (owner: WS-2, `inventory-service`)

Provider: `inventory-service`. Consumer: `order-service` (WS-3).

Everything below was captured **empirically** from the pre-migration Spring Boot 3.1.3
implementation (`master`, commit of `InventoryController`/`InventoryService`) running against a
throwaway `mysql:8.0` container, by `curl`-ing the running service. The Quarkus implementation
preserves it byte-for-byte on keys.

## Request

```
GET /api/inventory?skuCode=<sku>[&skuCode=<sku>...]
```

- The `skuCode` query parameter is repeated once per SKU. Repeated occurrences bind to a list.
- A single occurrence containing commas is also split into multiple SKUs
  (`?skuCode=a,b` is equivalent to `?skuCode=a&skuCode=b`). This is Spring's
  `List<String>` conversion behaviour and it is preserved.
- No request body, no headers required, no authentication at the service level (the API gateway
  terminates OAuth2).

## Response

- Status: **200 OK**.
- `Content-Type: application/json`.
- Body: a JSON **array** of objects with exactly two keys:

```json
[{"skuCode":"iphone_15","inStock":true},{"skuCode":"iphone_15_pro","inStock":false}]
```

### The boolean key is `inStock`, not `isInStock`

The DTO field is `boolean isInStock`; Lombok `@Data` generates the getter `isInStock()` and
Jackson's bean naming strips the `is` prefix, so the wire key is **`inStock`**. Verified
literally against the running pre-migration service:

```
$ curl -s 'http://localhost:8082/api/inventory?skuCode=iphone_15&skuCode=iphone_15_pro&skuCode=unknown_sku'
[{"skuCode":"iphone_15","inStock":true},{"skuCode":"iphone_15_pro","inStock":false}]
```

This matches the expectation WS-3 was given — no correction is needed.

### Semantics

- `inStock` is `quantity > 0`.
- **Unknown SKUs produce no array entry at all.** The lookup is
  `SELECT ... WHERE sku_code IN (...)`, so only found rows are mapped. The response array may
  therefore be shorter than the request list. There are **no** `{"inStock":false}` placeholders
  for unknown SKUs (see the `unknown_sku` in the capture above: three requested, two returned).
- All-unknown / no-match requests return **200** with an empty array `[]` (not 404).
- `?skuCode=` (present but blank) also returns `200 []`.
- Entries are returned in ascending primary-key (`id`) order of the matched rows.
- A request with the `skuCode` parameter **absent entirely** returns **400 Bad Request**
  (Spring's missing-required-parameter behaviour); the Quarkus implementation reproduces the
  status code, though the error body is Quarkus' own and is not part of this contract.

## Storage contract (informational for consumers)

MySQL schema `inventory_service`, table `t_inventory`, DDL as generated by the pre-migration app
(`SHOW CREATE TABLE`) and preserved identically by the Quarkus entity:

```sql
CREATE TABLE `t_inventory` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `quantity` int DEFAULT NULL,
  `sku_code` varchar(255) DEFAULT NULL,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci
```
